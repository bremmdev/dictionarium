`TenseLabel abbreviate` was checked with extra care: below `md` the visible header is the short Latin name (_Plūperf._, _Fut. exāct._). It is `aria-hidden` and inside the `lang="la"` span, and the full name stays readable as `max-md:sr-only`. A screen reader hears "Plūperfectum (pluperfect)" at every width. These are table headers, not controls, so 2.5.3 Label in Name does not apply.

## Fixed

- **The tense timeline's `alt` named six Latin forms** (`Translating.tsx:127`): _salūtāveram_, _salūtābam_, _salūtāvī_, _salūtō_, _salūtābō_, _salūtāverō_. `alt` is a flat string, so they were read with the English voice. The alt now names only the tenses, in English. The visible timeline and the table below still give the forms, with `lang="la"` in the table.

Also fixed along the way, outside the a11y rules:

- `Paradigms.tsx`: typo "are the the same as the fourth conjugation".
- `Paradigms.tsx`: removed `salūtō: <></>`. The empty fragment is truthy, so `Verb.tsx` rendered an empty `<p>` under salūtō's present table.

## Needs a decision

- **Health problem messages quote Latin data values** (`admin_.health.tsx:100`, `:191`, `:212`, from `utils/health/checks.ts`). Examples: `lemma_plain is "amo", should be "amo"` and `principal_parts is "amō, amāre, …" — …`. They're plain strings shared with `npm run check`, so they can't carry `lang`. Marking them would mean returning structured messages (text plus Latin parts) from the checks, for an admin-only page. Keeping them as they are seems reasonable: they are diagnostics about field values, not prose.
