The `/grammar/pronouns` meta description names _ego, tū, suī, hic, iste, ille, is, ipse_ and _īdem_. A `<meta>` value is a flat string and can't carry `lang`, the same limit as `aria-label`.

## Fixed

- **_capiris_ was in a plain `<em>`** (`conjugations/Paradigms.tsx`, the _capiō_ passive note): "_caperis_, not _capiris_". It is Latin, a form that doesn't exist, as `*tōte` and `ipsud` are on `/grammar/pronouns`. Now `<em lang="la">`, so it looks the same.
- **The enclitic on a form match was in a plain string** (`utils/inflection/describe.ts`): searching _virumque_ listed "with -que" as one more label, so the Latin _-que_ had no `lang`. A label is a flat string, so the enclitic now travels on its own as `FormLine.enclitic`, and `EntryCard`'s forms line renders it as `with <span lang="la">-que</span>`. The text on screen and in the screen reader is unchanged.
- **The pronoun filing hint in the admin form had _ego, meī_ in a plain string** (`admin/EntryForm.tsx`). `FILING`'s `hint` is now a `ReactNode`, and the pair gets `<span lang="la">`.
